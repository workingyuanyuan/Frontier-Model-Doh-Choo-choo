# Capability dimensions: semantic recommendation

Reviewed 2026-10-03 against `docs/BENCHMARK_DIMENSION_MAPPING.md`, `data/mappings/benchmarks.json`, the current display selection, and primary benchmark descriptions.

## Recommendation

Use **six dimensions** for the expanded catalog. Assign each Benchmark by the capability its score most directly measures; use domain, input format, and harness as context rather than as the capability label.

| Dimension                              | Capability boundary                                                                                                                                                     | Representative benchmarks                                                                     |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Reasoning**                          | Derive a solution from a problem statement: formal or scientific inference, calculation, proof construction, and non-document problem solving.                          | CritPt, ProofBench, Riemann-bench, competition mathematics                                    |
| **Knowledge**                          | Recall or apply factual, academic, or professional knowledge and rules. Keep correctness separate from calibration unless that calibration metric is actually imported. | AA-Omniscience Accuracy, Humanity’s Last Exam, MedCode, GPQA, MMLU-Pro                        |
| **Grounded Evidence Synthesis**        | Find, interpret, reconcile, and transform evidence supplied in a document, workbook, chart, transcript, or long context.                                                | AA-LCR, GDP.pdf, GDP.xlsx, Chartography, MedScribe                                            |
| **Coding**                             | Produce or modify a program, algorithm, or executable software artifact.                                                                                                | SciCode, IOI, Code Migration, Vibe Code Bench                                                 |
| **Agentic Workflow**                   | Complete a multi-step goal in a stateful, tool-enabled environment; the score depends on task progress or completion.                                                   | Finance Agent v2, GDPval-AA, AA-Briefcase, AutomationBench, H-Lab, EMB, Legal Research, Cyber |
| **Language and Instruction Following** | Understand and produce language, including satisfying explicit, conditional, and semantic output constraints when those constraints are the main scored skill.          | ComplexConstraints, IFBench, IFEval, LiveBench Language, Lech Mazur Writing, WMT24++          |

Grounded Evidence Synthesis is a coherent new axis if defined by **evidence dependence**, not context length alone. AA-LCR requires multi-document integration and inference; GDP.pdf asks for answers grounded in professional PDFs; GDP.xlsx requires reconstructing workbook logic across tabs, formulas, formatting, and comments; Chartography requires reading specialized visual evidence; MedScribe transforms a supplied clinical conversation into a structured note. These share a source-grounded endpoint even though their modalities and tools differ. [AA-LCR methodology](https://artificialanalysis.ai/articles/announcing-aa-lcr), [GDP.pdf AA page](https://artificialanalysis.ai/evaluations/gdp-pdf), [GDP.xlsx methodology](https://surgehq.ai/blog/gdp-xlsx), [Chartography](https://surgehq.ai/benchmarks/chartography).

Keep **Language and Instruction Following** separate. ComplexConstraints tests interdependent and implicit instructions in professional prompts, with the model answering in one completion and no tools or agent; its all-pass task rate is distinct from mean criterion satisfaction. IFBench and IFEval likewise score instruction constraints. They do not require retrieving or reconciling external evidence, so placing them under Grounded Evidence Synthesis would blur the construct. [ComplexConstraints description](https://surgehq.ai/benchmarks/complex-constraints), [official harness and metric definitions](https://github.com/surge-ai/complex-constraints).

## Ambiguous placements

- **MedScribe → Grounded Evidence Synthesis** (Language secondary). Vals asks a model to turn a doctor-patient transcript into a SOAP note under an expert-defined template and note-content rubric. The public leaderboard labels the imported metric **Accuracy**. Its methodology describes 80 transcripts (40 real and 40 simulated), expert-authored rubrics, and an LLM judge whose prompt was tuned to reach 80.5% agreement with majority human opinion across 180 checks. The public page does not fully specify the aggregate denominator or say that the headline is strict all-criteria task success. Describe it as rubric-scored note accuracy and completeness; do not call it generic prose quality or equate it to GDP.pdf all-pass. The weak observed association with LiveBench Language also cautions against treating it as a broad language score. [Vals MedScribe methodology](https://www.vals.ai/benchmarks/medscribe).
- **MedCode → Knowledge** (Grounded Evidence Synthesis secondary). The task assigns primary and secondary ICD-10-CM diagnoses from a full hospitalization record, using the CMS coding standard and expert-coded references. The patient record is essential evidence, but the scored professional skill is applying a specialized classification standard to that evidence. That separates MedCode from transcript-to-note generation. The domain is medicine; the capability is applied medical coding knowledge. [Vals MedCode methodology](https://www.vals.ai/benchmarks/medcode).
- **AA-Omniscience → Knowledge**, with a metric caveat. The benchmark was designed to study factual recall and hallucination, but this product imports its **Accuracy** result. The separate Omniscience Index combines accuracy and non-hallucination; do not describe the product’s Accuracy score as a calibration or hallucination score. [AA benchmark announcement](https://artificialanalysis.ai/articles/aa-omniscience-knowledge-hallucination-benchmark), [AA metric definitions](https://artificialanalysis.ai/evaluations/omniscience?iframe=yes).
- **Humanity’s Last Exam → Knowledge** (Reasoning secondary). It is broad expert academic question answering with short-answer and multiple-choice scoring; some questions require substantial reasoning, but the primary endpoint is correctness over academic subject matter. The current AA text-only evaluation uses a subset, distinct from the full multimodal set. [AA HLE evaluation](https://artificialanalysis.ai/evaluations/humanitys-last-exam).
- **CritPt, Riemann-bench, and ProofBench → Reasoning**. CritPt measures solving new research-level physics challenges; Riemann-bench asks for solutions to expert research mathematics; ProofBench asks for a machine-checked Lean proof. Their domains and answer formats differ, but their targets are problem solving and proof construction. Search, code execution, Lean, and agent loops are part of the evaluation method; they do not make these software-coding or workflow benchmarks. ProofBench’s use of Lean code is a proof representation, not the general software artifact measured by Coding. [CritPt AA methodology](https://artificialanalysis.ai/evaluations/critpt), [Riemann-bench methodology](https://surgehq.ai/blog/riemann-bench-a-benchmark-for-moonshot-mathematics), [Vals ProofBench](https://www.vals.ai/benchmarks/proof_bench).
- **GDP.xlsx tools → harness, not primary dimension**. The official harness runs an agent loop and allows spreadsheet tools, but grades only the final response text against task criteria. This makes the observed construct workbook-grounded reasoning and synthesis; tool-use demands are a secondary relationship. Treat a benchmark as Agentic when the scored endpoint is completing a stateful workflow, not solely because tools are available. [GDP.xlsx harness and grading](https://github.com/surge-ai/gdp-xlsx#grading).

| Language and Instruction Following | _No selected benchmark_                                                                                      |

Do not move MedScribe to Language or move instruction-following tests to Grounded Evidence Synthesis to fill that hole. The expanded catalog has a real Language dimension; the current selected cohort does not measure it. A complete top-six display should therefore show the five populated dimensions only, or use a different complete benchmark selection before showing Language.

This cohort also leaves Reasoning thin: it has CritPt and ProofBench, while ProofBench’s current top-six scores are 99–100% (mean 99.5%). That limits discrimination but does not change ProofBench’s semantic placement. CritPt is currently marked under review by Artificial Analysis, so its measured values may change with a revised evaluation. [ProofBench leaderboard](https://www.vals.ai/benchmarks/proof_bench), [CritPt status and methodology](https://artificialanalysis.ai/evaluations/critpt).

## Four-axis alternative

A simpler **four-axis** presentation can merge Reasoning and Knowledge into **Analytical and Expert Problem Solving**, beside Grounded Evidence Synthesis, Coding, and Agentic Workflow. This is a defensible coarse summary when breadth of score coverage matters more than diagnosis. It sacrifices the useful distinction between retrieving/applying learned facts and deriving a new answer from premises, so it is not my preferred catalog taxonomy. Keep Language as a catalog-level dimension even if the current six-model cohort cannot display it.
