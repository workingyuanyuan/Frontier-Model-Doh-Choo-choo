## v1.1.1 是否可比較

Vals v1.1.1 頁面（[vibe-code-v1-1-1](https://www.vals.ai/benchmarks/vibe-code-v1-1-1)）寫明「Vibe Code Bench v1.1.1 was released on November 23, 2026」，頁首與資料的更新日期則是 2026-11-21。頁面說明：

- 「does not change the tasks or the specifications the models build from」：題目與規格不變。
- 瀏覽器測試代理換成較新的模型與較新版 Browser Use；失敗的檢查另由第二位評審判斷，「A failure counts only if the evidence supports it」。
- 「An application now passes a test only when every substep succeeds. Before, 90% of substeps was enough.」
- 重新審閱 UI 測試，修正或移除無法完成或可有多種解讀的步驟（未公布數量）。
- 「We re-graded the applications that each model built in its Vibe Code Bench v1.1 run with the new grader. The models did not rebuild the applications」。
- v1.1 頁面標示「Archived Benchmark」，並寫「Vibe Code Bench v1.1 has been superseded by v1.1.1.」

結論：v1.1.1 測的是同一個能力（從 prompt 建出可運作的多檔 web 應用程式），harness 仍是 OpenHands，所以維度映射沿用 v1.1。但它的通過門檻更嚴、測試內容有修正，分數與 v1.1 不可互換：51 個兩版都有的模型組態，v1.1.1 全部比 v1.1 低，差距 0.73–25.72 分。

### 為什麼給新 ID，而不是把 `vibe-code-bench` 改指向 v1.1.1

- SPEC 規定需要分開計分的版本必須有自己的 benchmark ID；Terminal-Bench 4.1 取代 4.0、FrontierMath v2 取代 v1 都是這樣做。
- 兩版分數不可比。若共用同一個 ID，同一個 benchmark 底下會同時有 v1.1 與 v1.1.1 的列，產品的去重與共同測試計算無法分辨版本。
- v1.1 有 134 列、v1.1.1 只有 51 列。另給新 ID 後，v1.1 的 134 列完整保留為證據，v1.1.1 補上更多模型時也不必再遷移。
- 兩版都計分會讓同一批應用程式被算兩次，所以 v1.1 由品質政策排除。
