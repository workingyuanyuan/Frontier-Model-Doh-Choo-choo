# 2026-11-18 資料刷新報告

完整 release 通過，**沒有重大變更**：OpenAI 新模型 GPT-6.2 Astra 與 GPT-6.2 Sol 依官方證據登記後進入前沿前 10 名，預設集合依既有規則由 `aa-top-10` 收斂為 `aa-top-8`。計分政策未變，名次變動都來自新模型加入與共同測試組成改變。判斷依據見「重大變更判斷」。

本次重點如下：

- **新模型 `GPT-6.2 Astra`（`openai-gpt-6-2-astra`）與 `GPT-6.2 Sol`（`openai-gpt-6-2-sol`）**：OpenAI 於 2026-11-17 發布，官方模型頁列出 API ID `gpt-6.2-astra`、`gpt-6.2-sol`。首日即出現在 AA、LiveBench、FrontierCode、Epoch、ARC Prize、Vals 與 Zapier 7 個現役來源。AA Intelligence Index v5.0.1：Astra Max `62.14`（第 2 名）、Sol Max `57.26`（第 5 名）。
- **預設集合 `aa-top-10` → `aa-top-8`**：前 8 名的共同測試由 8 項增為 9 項（加入 `automationbench`），加入第 9 名後回到 8 項，依 2026-10-23 使用者裁決「測試數相同才延伸」停在 8 個模型。
- **建置程式修正**：Vals 新增一筆已排除的 `robo-bench` 成績，指向沒有計分 profile 的 `alibaba-qwen3-8-max-high`，使「evidence 引用的 profile 必須存在」的不變量測試失敗。已修正 `buildProduct`（見「依證據自行決定的事項」）。
- **`Astra for Law 6.2` 不登記為模型**：官方說明它是 GPT-6.2 Astra 加上法律搜尋索引與指令的「model configuration」，維持未對應。

官方公告、上游探索與研究候選見 [每日查核](../research/2026-11-18-benchmark-update-check.md)。

### 依證據自行決定的事項

- **登記 GPT-6.2 Astra 與 GPT-6.2 Sol**：依 [GPT-6.2 Astra 模型頁](https://platform.openai.com/docs/models/gpt-6.2-astra)、[GPT-6.2 Sol 模型頁](https://platform.openai.com/docs/models/gpt-6.2-sol) 與 `openai.com/news/` 的 2026-11-17 發布條目，以精確 aliases `gpt-6.2-astra`／`gpt-6-2-astra`／`openai/gpt-6.2-astra`（Sol 同式）加入 `data/mappings/models.json`，`releaseDate: 2026-11-17`。先完成第一次匯入確認各來源名稱，再登記身分、重跑 7 個含新模型的來源與 `effort-reports`，253 列全部正確對應。
- **`Astra for Law 6.2` 不登記**：官方 [Astra for Law](https://openai.com/index/astra-law-6-2/) 說明它是「a model configuration of GPT‑6.2 Astra」，搭配擴充的法律搜尋索引與指令。依既有做法不把 harness／工具配置拆成模型，也不併入 GPT-6.2 Astra 以免混入工具加成的成績；AA 未公布其 Intelligence Index，不影響前沿判定。
- **建置程式修正（`packages/benchmark-data/src/index.ts`）**：產品的 `evidence` 收錄前沿模型全部成績（含已排除者）以供稽核，但 profile 只來自有比較或集合成績的計分結果。Vals 新增的已排除 `robo-bench` 成績是 Qwen3.8 Max 的 `high` effort，而這個 effort 沒有任何計分成績，於是 evidence 指向不存在的 `alibaba-qwen3-8-max-high`。修正後，profile 未發布的 evidence 列保留在模型底下、`profileId` 設為 null，分數、名次與成本皆不受影響。新增一個合成資料的最小測試（`pipeline.test.ts`「detaches an excluded result whose effort has no scored profile」），未修正時失敗、修正後通過。Codex（`gpt-6.1-sol`）審查指出初版對 INCLUDED 列拋錯會讓品質政策排除的合法情形建置失敗，已改為一律設為 null。
- **AA 的 deprecated 標記**：AA releases 目錄把 GPT-6 Astra 與 GPT-6.1 Sol 標為 deprecated；本專案的模型目錄不讀取此旗標，兩者仍是現役 API 模型，照常參與排名。

## 重大變更判斷

依 [OPERATIONS §5](../OPERATIONS.md#5-代理驗證與異動判斷)：

- **集合結果**：前沿前 10 名的變化完全來自兩個有官方證據的新模型加入（AA 第 2、5 名）。預設集合由 `aa-top-10` 改為 `aa-top-8` 是既有「測試數相同才延伸」規則的結果，屬可直接套用並告知的預設集合重排。
- **計分口徑**：計分政策、門檻與 benchmark 品質政策都沒有變。唯一的程式修正只影響已排除 evidence 的 `profileId` 欄位，不改分數、名次或成本。
- **身分與資料差異**：GPT-6.2 Astra／Sol 有 OpenAI 官方模型頁與新聞條目支持；`Astra for Law 6.2` 依官方說明不登記。AA 的移除列都是未對應模型；Epoch ECI 重新估計不計分；FrontierSWE 兩筆小幅調整來自上游重算。沒有無法解釋的變動，也沒有需使用者裁決的計分或來源政策。

因此判定為 **沒有重大變更**。
