- **官方資料**：榜單頁 <https://agents-last-exam.org/leaderboard> 是 JS shell。資料端點 `https://agents-last-exam.org/api/demo/leaderboard/v1.1` 是從頁面 bundle 中找出的，匯入時也會再確認 bundle 確實請求這個端點。
- **資料時點**：`resultsUpdatedAt` 為 2026-11-18T01:01:54Z，`costRatesAsOf` 為 2026-11-17。題目定義 commit 為 `2e91edd`（2026-10-27）。
- **規模**：共 41 列、122 題（Linux 86 題、Windows 36 題）。

  - 分數採 `avgScore × 100`（平均任務分數，%）。

- **匯入時的驗證**（任一項不符就停止匯入）：
  - 每列的 runs 必須等於 tasks；
  - 欄位齊全且為有限數值；
  - 版本一致；
  - 平台題數為正整數；
  - 每個設定的 Linux 與 Windows 列，相加後要等於整體列的 passes、tasks 與成本（成本容許每平台一分錢的進位誤差）；

- **列數**：41 列全部 INCLUDED。36 列對應到模型；5 列未對應，依「不模糊比對」維持未對應：`glm-5.3`、`kimi-3.1-pro`、`qwen-4`，以及 `minimax-m3-1-flash`（codex 與 claude_code 各一列）。

### 依證據自行決定的事項

- **`reasoning-none` 一律對到 `non-reasoning`**：ALE 把 `harnessVariant` 當作明確的 reasoning-effort 設定傳給 harness，所以 `none` 是刻意關閉推理的執行，不是「沒有標示」。FrontierCode「只有單一 `none` 時保持 null」的規則不適用。
  - 第一版沿用 FrontierCode 規則，結果 GPT-5.6 Luna 唯一的 `reasoning-none` 列被跨來源推定到 `luna-max`。抽查代理標出這一點；產品裡已有 `luna-non-reasoning` profile。
  - 修正後這一列與成本都歸到 `openai-gpt-5-6-luna-non-reasoning`。
- **同一模型和 effort 在多個 harness 出現時，全部排除，不擇一**：本次沒有發生，MiniMax M3.1 Flash 的兩列本來就未對應。
- **ALE 在進階成本圖預設不啟用**：GPT-6.1 Sol 與 Sonnet 5.5 沒有 ALE 成績，預設啟用會讓它們離開初始圖。
- **`tencent-hy4-default` → `tencent-hy4-high`**：ALE 是唯一明確標出 Hy4 effort 的來源（claude_code、reasoning-high）。依既有的跨來源推定規則，AA 與 Vals 的未標示列改歸 `high`。Hy4 不在任何 preset。
- **未新增任何模型 alias**：`Hy4`、`muse-wonder-1.0`（→ Muse Wonder）、`deepseek-deepseek-v4-1-flash-1017` 都是既有 alias。`kimi-3.1-pro` 缺少「K」，`qwen-4` 與目錄裡的 Qwen4 Max 名稱不同，都不做模糊比對。
