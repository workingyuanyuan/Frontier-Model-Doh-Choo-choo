### 依證據自行決定的事項

- **登記 Gemini 4 Neon**：證據是 [Google 公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)（2026-11-18）與 [API 模型頁](https://ai.google.dev/gemini-api/docs/models/gemini-4-neon)（model code `gemini-4-neon`，Stable）。依此以 aliases `gemini-4-neon`、`google/gemini-4-neon` 加入 `data/mappings/models.json`，`releaseDate: 2026-11-18`。
- **Vals 的 Neon 代號**：Vals 用內部 model key `google/cobalt-c-high-1p00`，它的 [Gemini 4 Neon 模型頁](https://www.vals.ai/models/google_gemini-4-neon) 標題與 h1 都是 Gemini 4 Neon，Vals Index `70.873%` 也與 Google 公告的「70.9%」一致。因此把這個 key 列為精確 alias，重跑 Vals 後 14 科都對應到 `google-gemini-4-neon-xhigh`。effort 取自 Vals 資料欄位 `reasoning_effort: xhigh`，代號中的 `high` 不影響判定。
- **Surge Chartography 照常採用重算後的成績**：主榜確認為頁面的「Chartography Leaderboard」，41 列與渲染列數相符。重算來自上游，比照「benchmark 改版時跟隨新版」處理，並在此揭露。Google 公告引用的 Neon Chartography `73.5%` 與 Surge 今日顯示的 `86.6%` 不同，推測公告撰寫時尚未重算，但沒有官方說明。這次重算只影響 `aa-top-2`；其中 Fable 5.2 與 Astra 都是今日首次出現在這個榜。
- **CursorBench 4.0 交叉核對**
  - **起因**：Cursor 官方榜在 11/18 由 4.0 升到 4.1。舊的檢查只確認頁面上有「CursorBench 4.0」字樣，而這段文字仍留在 changelog 裡，所以 4.0 的廠商成績被拿去和 4.1 的榜比對，廠商來源刷新因此失敗。

    - 版本改從結果區塊的 `aria-label` 讀取，分數也只從該區塊讀取。
    - 只有明確審核過的「4.0 → 4.1」轉換，才會改用寫死在程式裡的 4.0 擷取（`sha256:b408dbff…`，2026-11-18T04:58Z，讀取時核對 SHA-256）。
    - CursorBench 列必須是 4.0／accuracy 才會比對。
    - 離線重建也會產生同樣的說明。

## 重大變更判斷

依 [OPERATIONS §5](../OPERATIONS.md#5-代理驗證與異動判斷) 判斷：

- **集合結果**：前沿前 10 名的變化完全來自一個有官方證據的新模型加入（AA 第 3 名）。預設集合由 `aa-top-8` 改為 `aa-top-9`，是既有「測試數相同才延伸」規則的結果，屬於可直接套用並告知的預設集合重排。舊預設 8 個模型的分數都沒有改變。
- **計分口徑**：計分政策、門檻與 benchmark 品質政策都沒有變。兩項程式修正只影響擷取與交叉核對，不改分數、名次或成本。
- **身分與資料差異**：
  - Neon 有 Google 公告與 API 文件支持；Vals 代號有 Vals 模型頁與公告數值互相印證。
  - AA 移除的列都是未對應模型；Epoch 與 Zapier 的 ID 變動是列號重排。
  - Chartography 的重算來自上游，已確認讀取的是主榜，只影響 `aa-top-2`，不影響預設集合與 3～10 名的集合。
- **待使用者決定的事項**：Surge DAYJOB: Law、Vals Autoform-Hard 等新 benchmark 只列為研究線索，沒有收錄，也不阻擋本次提交。

因此判定為 **沒有重大變更**。
