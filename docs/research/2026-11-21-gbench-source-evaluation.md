# 2026-11-21 來源評估：GBENCH（Gert Labs）

> **使用者裁決（2026-11-21）**：採用選項 A，只採 Agentic Coding GScore，主維度 Coding、次要 Agentic 與 Reasoning。實作與產品影響見 [刷新報告](../refresh/2026-11-21-gbench-adoption.md)。

**結論**：值得收錄，但只建議採用 Agentic Coding 一項，放在 Coding 維度。採不採用、計分口徑和維度由使用者決定（[AGENTS.md](../../AGENTS.md)）。本評估沒有改動任何資料或程式。

- 優點：
  - 前沿窗口 10 個模型都有成績。依 effort 投票規則估算，9 個模型會落在代表 profile 上。例外是 Gemini 4 Neon：成績會落在 high，而代表 profile 是 xhigh。
    - `aa-top-2` 不含 Neon，會多一項共同測試；含 Neon 的 `aa-top-3`～`aa-top-10` 不會。
    - `coverage-2`～`coverage-8` 不含 Neon、`coverage-10` 已用 Neon high，各多一項。
    - `coverage-9` 目前用 Neon xhigh，要等重新搜尋才知道。
  - 前沿模型之間分數拉得開。
  - 方法公開，資料有 JSON。
- 主要風險：
  - 沒有 effort 和版本。
  - 分數是相對值，會隨新模型、新遊戲重新平衡。
  - 對前沿模型的排序和本專案現有結果差異很大，見「與現有資料的對照」。
  - 預設集合 `aa-top-9` 依現行規則不會納入：Neon 的成績推論落在 high，與代表 profile xhigh 不同。

證據：[評估 JSON](2026-11-21-gbench-source-evaluation.json)，內含前沿 10 個模型的逐列數值與相關係數。API 取得時間是 `2026-11-21T12:27:54Z`。對照的產品版本是 `sha256:19752c094251c2413f33e7a22f727b1259a061f3a0834ed405fd5ca1e493e6aa`。

## 來源概況

| 項目     | 內容                                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主辦     | Gert Labs Inc.，同時是 benchmark 主辦方與執行者（角色 ORGANIZER）                                                                                                                                    |
| 測法     | 模型在多人遊戲中對戰，遊戲可以是合作或對抗，目錄會自動生成並持續擴充。分三種模式：Agentic Coding（多輪工具迴圈寫遊戲程式）、One-shot Coding（單次提交程式）、Decision Making（每個 tick 直接選動作） |
| 指標     | GScore，顯示為 0–100。每個遊戲內依同模式對手排名，再以固定效應模型扣除各遊戲的對手強度，換算成調整後百分位。取平均與中位百分位的幾何平均，再乘上成功率的四次方根                                     |
| 綜合分數 | 三種模式加權：Agentic 40%、One-shot 45%、Decision 15%                                                                                                                                                |
| 規模     | 排行榜 100 個模型（含一列 Human），每個前沿模型 56–76 個遊戲、2.3 萬～18.8 萬場對戰                                                                                                                  |
| 不確定性 | 綜合與各模式都附信賴區間，少數模型沒有，例如 Gemini 4 Carbon                                                                                                                                         |
| 資料取得 | 頁面以 JavaScript 渲染。`/api/v1/global/rankings` 免登入回傳 JSON（約 12 MB），含各模式分數、逐遊戲百分位、成本與失敗統計。`/api/v1/charts/model-performance` 另有逐次提交紀錄                       |
| 方法文件 | [Benchmark Fatigue（2026-04-06）](https://gertlabs.com/blog/gbench-1) 的 Benchmark Methodology 一節                                                                                                  |
| 條款     | [Terms（2026-02-12）](https://gertlabs.com/terms) 只禁止濫用服務和規避限流，沒有提到資料再利用                                                                                                       |

不符的「版本與 Profile」可用現行規則處理，但會降低可追溯性：

- **effort**：依 [來源優先規則第 3 點](../BENCHMARK_SCORE_SOURCES.md#採用與覆蓋規則)，未標 effort 的列由其他來源同一模型的具名檔位投票決定。GBENCH 實際可能用 OpenRouter 的預設值，所以這只是推論，報告要揭露。

  我以 `current.json` 中各來源明示的 effort 估算投票結果（正式結果以實作為準）：

  - 8 個模型會落在 max，Gemini 4 Hydrogen 落在 xhigh、Gemini 4 Carbon 落在 high，都和代表 profile 一致。
  - Gemini 4 Neon 的票是 high 14、xhigh 7，所以會落在 high，和代表 profile xhigh 不同。

- **版本**：可以把版本記為 null，以快照日期追溯。但每次刷新都可能改動所有舊模型的分數，刷新報告會固定出現這個來源的大量變動。

- **區辨力**：前沿 10 個模型的 GScore 範圍是 69.9–92.0，標準差 6.2。有信賴區間的 36 組配對中，只有 10 組區間重疊，沒有本專案排除的飽和題庫那種天花板效應。

既有先例：本專案已採用相對型指標，例如 GDPval-AA（由 Elo 換算的正規化分數）和 AA MKA（Climb WSR）。所以「分數是相對值」本身不是排除理由。

## 計分方式選項

| 選項 | 採用內容                                                          | 影響                                                                                                                                                                                                |
| ---- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A    | 只採 Agentic Coding GScore，一項 benchmark，主維度 Coding（建議） | `aa-top-2` 與多數 `coverage-N` 多一項共同測試；含 Neon 的 `aa-top-3`～`aa-top-10`（包括預設的 `aa-top-9`）因 effort 對不上不會增加。Coding 只有一兩項的集合影響明顯，但只算一項，不會由單一組織主導 |
| B    | 綜合 GScore 一項                                                  | 會帶入 15% 權重、樣本極少的 Decision 模式                                                                                                                                                           |
| C    | Agentic 與 One-shot 各算一項                                      | 兩項來自同一批遊戲和模型，彼此高度相關。Coding 只有一項的集合，該維度會有三分之二來自 GBENCH                                                                                                        |
| D    | 暫不採用，列入每日查核的觀察名單                                  | 等 GBENCH 公開 effort 設定或版本後再評估                                                                                                                                                            |

選 A 的理由：

- Agentic 模式最接近現有 Coding 題庫的執行方式（FrontierCode、SWE Atlas 都是多輪代理）。
- 每個前沿模型都有 24–36 個遊戲，樣本足夠。
- 只算一項，可以避免單一組織在維度裡的占比過高。
