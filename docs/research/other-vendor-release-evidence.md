## MiMo-V2.6

The Xiaomi release page reports the before/after live-RL sequence on DeepSWE v1.1: Flash 48.8→65.7 and Pro 58.4→72.6. Its surrounding text describes the six-day training process and its 30 training steps. It does not label the endpoint as the final released checkpoint’s score, so neither endpoint should be materialized as a release result without a final-checkpoint statement from Xiaomi.

The same page reports SWE-bench Verified 61.1→66.2, MiMo Cyber Bench 31.3→47.0, Terminal-Bench 2.1 37.1→52.8, and MiMo Visual Coding 64.0→72.4 for RL training that starts from **MiMo-V2.6-Distill-Qwen-9B**. These are results for a separately named distilled/training artifact, not the released Pro/Flash models. The Cyber and Visual Coding benchmarks also have no matching catalog entries. Keep all four out of Pro/Flash profiles.

The [Pro model page](https://mimo.mi.com/models/en-US/mimo-v2.6-pro) gives current token rates of $0.435/M input cache-miss tokens, $0.0036/M cache-hit input tokens, and $0.87/M output tokens. The [Flash model page](https://mimo.mi.com/models/en-US/mimo-v2.6-flash) gives $0.14/M cache-miss input, $0.0028/M cache-hit input, and $0.28/M output. These are API token prices, not task costs for a benchmark run. The Pro page’s 46.32 Artificial Analysis composite index is an aggregate, not an ID in `data/mappings/benchmarks-v2.json`.

## Meta Muse Spark 1.3

The official [evaluation-methodology PDF](https://research.meta.ai/static/muse-spark-1-3-multimodal-evaluation-methodology) says Muse Spark 1.3 results use the Meta Model API and max reasoning effort. It identifies mini-SWE-agent as the Muse Spark 1.3 harness for DeepSWE v1.1 and defines task pass rate as the primary metric. The linked [official scorecard image](https://research.meta.ai/articles/introducing-muse-1-3/benchmarks/benchmark-scorecard-v6.webp) reports **75.4**. The row candidate is:

| Model/profile        | Benchmark/version | Score/metric | Harness and method                                 | Cost                  |
| -------------------- | ----------------- | ------------ | -------------------------------------------------- | --------------------- |
| Muse Spark 1.3 / max | DeepSWE v1.1      | 75.4% Pass@1 | mini-SWE-agent; Meta Model API; long-horizon tasks | Not reported per task |

Other scorecard numbers with catalog matches are not safely interchangeable with current product evidence. GDPVal-AA is 1,754 Elo on Meta’s “v2” scorecard, while local Artificial Analysis evidence is `gdpval-aa` v2.1 and stores normalized percentage; both the version and metric differ. Terminal-Bench 2.1 is 88.8% at max using each model’s native coding harness in Meta’s internal framework, versus the existing local Artificial Analysis Muse Spark 1.3/max result of 84.2697% and Vals max result of 79.026% (both source records label Terminal-Bench 2.1). Keep the scorecard number as a discrepancy lead; do not override the independent record until the harness/run difference is reconciled.

The scorecard reports OSWorld 2.0 **66.9 partial** and **32.0 binary** at max. Meta’s methodology states the primary metric is mean per-task partial score and this model used release version 08.08. The local OSWorld organizer dataset currently records v2026.06.24-steps-500. Preserve 08.08 as a candidate version and hold it outside the current comparison until that release is added and version equivalence is adjudicated.

AutomationBench is **49.6%** at max, but Meta says it ran the public v3 task set. The current local Zapier organizer row for this model is **20.7%**, version 1.0.6 on the official held-out leaderboard. The benchmark page states the official leaderboard uses held-out private tasks, distinct from the public set. Do not treat Meta’s public-v3 result as a replacement for 1.0.6; only consider it after the project adds a separate public-v3 identity.

The same scorecard reports MRCR v2 mean sequence-match ratios of **98.5** for 8-needle 256K–512K and **98.1** for 8-needle 512K–1M, with 100 examples in each band. `mrcr-v2` exists in the catalog, but the bands are separate task populations and the project currently has no corresponding rows. Add explicit band identities/metrics before using both values in a comparison.

JobBench 64.9, DeepSearchQA 90.3, and SWE-Atlas Codebase QnA 59.4 have no benchmark IDs in the current catalog. The 57.8 Agentic IF Index is Meta-internal and is not the public IFBench. Do not import these as existing benchmark rows.

## MiniMax M3 and Step 5 Preview

MiniMax’s release page says M3 reached **59.0% SWE-Bench Pro** and **66.0% Terminal-Bench 2.1**. Its methodology describes SWE-Bench Pro as an internal run using Claude Code with logic aligned to the official evaluation. That exact benchmark ID exists locally and there is no local MiniMax M3 `swe-bench-pro` row; it remains deferred until benchmark version and organizer overlap are established. The page does not publish an attempt count, thinking-mode setting, or per-task cost. Retain those fields as undisclosed/null and preserve the inference that effort is max under the project’s same-model voting rule.

For the 66.0 Terminal-Bench 2.1 claim, MiniMax states: internal run, Terminus 2 scaffold, 8C16G sandbox, two-hour timeout, and 128K max output tokens. Current local competing evidence is Artificial Analysis MiniMax M3/max **65.1685%** (independent) and Vals MiniMax M3/max **53.558%** (independent). The release number is not the selected product value under the documented source-role priority. The M3 page’s other claims—SWE-fficiency 34.8, KernelBench Hard 28.8, MCP Atlas 74.2, PostTrainBench 37.1, and multiple internal workflows—do not map to current catalog entries or are internal composite tasks. Keep them out of existing rows.

StepFun’s [platform page](https://platform.stepfun.com/) establishes availability of Step 5 Preview but has no model benchmark scores. The [Step Code page](https://platform.stepfun.ai/step-code) reports Step Code at **73.3% completion** and **5.09M tokens/task** on Multi-Frame BMK in a six-agent comparison using Step 5 Preview. The result measures an agent-model pair, lacks a benchmark catalog identity, and reports tokens rather than USD. It is not a model score or task cost to import.
