**維度層的變動比 Overall 大得多，方向也一致，值得先理解再抽查。** 原因是 Epoch 的
benchmark 進入了維度平均——維度分數使用**所有可得的** benchmark，不只顯示清單裡的：

- **reasoning 普遍下降 4～9 分**：`chess-puzzles` 加入 reasoning，而它是難題（主畫面模型
  落在 33～64），把平均拉低。這不是模型變差，是量尺變嚴。
- **math 普遍上升 1～4 分**：`aime` 加入 math。
- **knowledge 有升有降**：`simpleqa-verified` 加入 knowledge。
- **coding 個別上升**：`swe-bench` 加入 coding（DeepSeek V4 Pro +5.11）。

例：Claude Opus 5 的 reasoning 71.20 → 61.81，math 95.73 → 96.75，淨效果 Overall −1.09。

  檔案，但都還沒有核可的 benchmark ID 與維度對應。要納入必須先走 §5.3 的報告與裁決。
- **ECI 有 1026 列無法解析為 catalog identity**：多數是回溯到 2023 年、不在 catalog 內的

- **Epoch 沒有成本資料**：因此不進 §7 的成本權重表，進階圖仍是三來源。若日後 Epoch 公布
  成本，權重表需要重新決定，不能直接套用等權重。
- **token 預算後綴（`_32K`、`_16K` 等）與 `_unknown` 仍為 null effort**，會走 §4.5 推測。
  目前沒有任何一筆落在主畫面 profile 上，但來源若擴大使用這些後綴就需要重新檢視。
- **`versionId` 含 `generatedAt`**，每次 build 都會變，不能當作「內容有沒有變」的判準。
